# 发送后情境反应测试计划

日期：2026-11-03。对应 [当前设计](INTENT-AWARENESS.md)。连接配置、新增短消息到主动气泡已接入；自动草稿采集未接通。下方测试清单是验收标准，执行情况集中见文末本轮验证记录，不能将全部清单视为通过。

## 测试分层与执行顺序

1. 事件来源可行性：确认推荐实际展示、用户成功发送、聊天/输入轮次和顺序可读取，并测量事件发现延迟。这是即时反馈成立的前提。
2. 隔离策略验证：以虚拟时间、假发送事件和假网络端点验证配对、长度、关闭、去重与迟到丢弃。验证可观察的请求次数、请求字段和展示次数，不测试内部实现细节。
3. Jev 实验：使用预先标注的合成短消息，通过本用户指定的 7897 代理调用模型，分别记录语义分类与最终策略动作。配置测试另外验证不同服务地址、其他代理端口和直连，后两者使用本地假服务，不向真实服务发起直连。
4. 桌面端到端：在隔离 CODEX_HOME/WHALE_HOME 下运行，验证真正从发送到气泡的耗时、优先级、可见性、焦点和开关。不得影响日常运行的桌宠。
5. 相关回归：实施后跑受影响的 suite、包校验；若修改 runtime，按仓库规定跑完整 npm test。涉及 macOS 原生行为的测试在 Mac 顺序执行，不用 Windows 结果代替。

默认关闭、超长不上传、错配推荐、关闭后迟到结果、真实提问被覆盖和绕过代理属于阻断发布的问题。模型偶尔漏掉一次可选反应单独计数，不为提高命中率放宽这些规则。

| 编号 | 操作 | 必须观察到的结果 |
| --- | --- | --- |
| A01 | 推荐展示后按发送按钮 | 得到同一聊天/输入轮次的已展示文本和实际提交文本，顺序正确 |
| A02 | 推荐展示后用快捷键发送 | 与按钮路径相同，不重复产生两个提交 |
| A03 | 用户先发送，推荐随后到达 | 当前消息无推荐，不反向补配 |
| A04 | 推荐生成但没有实际展示 | 不标为已出现 |
| A05 | 提交失败/被取消、仅编辑草稿 | 不触发分析 |
| A06 | 一次发送同时被两个监听源发现 | 合并为同一消息，最多一次请求 |
| A07 | 在同一线程多次出现完全相同文本 | 使用提交身份区分真实新发送与重复事件 |
| A08 | 监听重连/启动重放 | 历史提交不产生新反应 |

记录事件源、字段可用性、先后依据和发现延迟；不采集不必要的聊天正文。若只有文件写入顺序，必须说明无法证明界面展示顺序，不把它当成 A01 通过。

## B 推荐配对、长度与上传边界

| 编号 | 输入条件 | 预期 |
| --- | --- | --- |
| B01 | 先前推荐与发送内容完全相同 | paired + exact；不要求点击标识 |
| B02 | 仅首尾空白、CRLF/LF、NFC 等价差异 | 本地 exact |
| B03 | 同义改写 | paired + different，交 Jev 判断语义 |
| B04 | 增加“不”、改变数字或代码 | 不被归一化误判成 exact |
| B05 | 推荐来自另一个聊天/输入轮次 | 用户消息分支；请求不含旧推荐 |
| B06 | 显示时间与提交先后无法区分 | 用户消息分支 |
| B07 | 推荐显示后撤回、失效或被替换 | 仅有效最新快照可用；不得复活旧推荐 |
| B08 | 发送后产生新推荐 | 原请求快照不变 |
| B09 | 归一化后 299、300、301 个 Unicode 码点 | 前两项可分析，301 本地拒绝且请求数为零 |
| B10 | 表情符号、组合重音、汉字混合 | 按码点和 NFC 约定计数，不用 UTF-16 长度误判 |
| B11 | 空消息、只有附件 | 不分析、不读取附件 |
| B12 | 用户消息超长且开头有强情绪 | 整条拒绝，不截取开头上传 |
| B13 | 单条推荐 301 或总推荐 901 码点 | 丢弃整份推荐，只发送合格用户消息 |
| B14 | 无推荐分支 | 请求只有本条用户文本及固定判断说明，不含历史助手/工具/会话内容 |
| B15 | 消息包含否定、引用、测试代码 | 内容原样保留给语义判断，不通过删标点或关键词提取改变意思 |

| 编号 | 事件序列 | 预期 |

关闭后的网络测试区分“取消本地等待”和“服务端已经收到请求”，不能把后者记为可撤回。请求数以实际发出为准。

## D Jev 语义数据集

每例在请求前固定可接受答案。至少覆盖：exact、同义采纳、附加修改、明确否定、弱情绪、强喜悦、强疲惫、强愤怒但赶工、引用别人情绪、代码字符串、讽刺、混合情绪、要求安静、提示词注入，以及发送后才出现推荐的用户消息分支。

当前实现分别统计 relation、emotion、hold_back、occasion 和最终动作，语气由合格证据与固定人设决定。主指标为错误开口、漏掉合理反应、错误得意、错误台词前提；不要只汇报选句命中率。没有推荐而得意、弱情绪被当作强情绪、明确要求安静却开口，单列错误。

第一轮合成集用于发现问题，不用于宣称总体准确率。阈值或问题措辞修改后，应另建未参与调整的验证集；真实端到端验收前，目标至少 40 个独立短消息情境，其中不少于一半应保持安静。该规模是验收安排，不代表本次已发送 40 个付费请求。

## E 气泡与使用体验

| 编号 | 场景 | 预期 |
| --- | --- | --- |
| E01 | 发送短回复、判断为得意 | 正确气泡贴近本次发送出现，不先弹假反应 |
| E02 | Jev 判断沉默 | 不增加气泡、音效或等待提示 |
| E03 | 随机台词正在显示 | AI 反应按设计替换；结束后旧随机台词不补播 |
| E04 | 提问/授权、额度查看、菜单或完成统计在显示 | 按设计优先级丢弃 AI 反应，不挤占业务展示 |
| E05 | AI 气泡出现后用户继续输入 | 不抢键盘焦点、不弹窗口、不要求回复 |
| E06 | 连续符合条件的发送 | 最多一个 AI 气泡、10 秒展示间隔，不延期排队 |
| E07 | 重复情境 | 不连续用同一句；无合适备选时安静 |
| E08 | 部分任务完成、非代码疲劳 | 不说“收工”或“代码先晾着” |
| E09 | 三句 chat 文案 | 本版不会选择，不出现邀请继续聊天的交互 |
| E10 | 用户收起气泡 | 不追问、不表现委屈、不立即换一句 |

角色鼠标移入避让本期不做，不把已有遮挡问题误报为修复；端到端检查确保本功能没有新增焦点、按钮或更大的交互阻挡范围。

## 耗时与资源测量

分开记录：成功提交到事件发现、快照构建、代理/TLS、API 响应、展示排队和首次可见帧。旧实验中“不含连接的 API 耗时”不能代替端到端时延。

在代理正常的测试机上至少 20 次可展示事件，汇报完整分布和超时丢弃数；目标 P95 在 1 秒内首次可见，超过 2 秒的结果绝不显示。目标未达时如实保留失败，不先演一条未经判断的台词。平台差异分别记录。

开启但没有新消息时不轮询 Jev；关闭时不新增本功能的内容监听。观察 10 分钟空闲时的请求计数和本功能计时器活动，结束测试即停，不建立持续监控。该观察属于实施后的验收安排。
