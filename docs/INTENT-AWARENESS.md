# 小龙娘发送后情境反应设计

更新：2026-11-03。状态：已实现 Jev 连接配置、新消息监听、用户短消息判定与主动气泡，并修复历史提问复活，已作为 0.1.5 本地验证版安装到本机。用户接受仅依据已发送回复作反应；输入框自动草稿采集仍未接通，保留配对规则而不冒充实时采集。功能默认关闭。

## 已确定的边界

- 可选的 Jev 情境反应，默认关闭；检测到 API key 也不自动开启。
- 没有聊天窗口、输入框、多轮聊天、聊天记录、生成式台词模型。只选择用户提供的固定台词，说完即止。
- 唯一常规触发点是用户向 Codex 成功发送消息。优先在发送后立即给到一次明确的角色反馈，不在空闲时随机搭话。
- 比较发送前已出现的 Codex 预设回复与用户实际发送内容。无需证明用户点击过推荐按钮。
- 发送时尚无可用推荐，仅以当前用户消息判断强烈情绪；普通指令、轻微情绪、长消息保持安静。
- 鼠标移入半透明、停留显露与摸头意图判定本期暂缓，不作为本功能的前置工程。
- 额度、真实提问和授权提醒继续独立运行。原有提问误报已按提醒生命周期修复，不交给 Jev 猜测。

当前可用链路是新增用户纯文本消息 → 长度校验 → Jev 强情绪判断 → 固定台词气泡。默认关闭，只有明确启用后才启动监听。推荐缺失时不制造配对证据，不会在实际运行中触发得意。

## 开关的完整语义

设置项“发送后情境反应（Jev）”初始为关闭；保存用户选择，重启不擅自改变。更新时没有这个设置的旧安装也按关闭处理。

关闭时不为本功能读取消息内容、采集推荐或调用模型。原有额度与提醒服务按原职责工作。关闭瞬间停止接收候选，取消可取消的网络等待，清空短期推荐/消息缓存，关闭当前 AI 反应气泡，废弃全部在途结果。已发到服务端的请求可能已产生费用，不能承诺撤回。

重新开启只接受开启之后的新事件；不扫描历史来补发，也不利用关闭前缓存的推荐。停用、进程重启和断线重连都遵守同样规则。

启用后会将合格短消息发送给所配置的 Jev 服务作判断，使用所选网络方式。设置页包含实际生效的 enabled 开关，并明确说明输入框草稿采集的限制。密钥不可用或代理失败时保持安静，不反复弹错误气泡。

## 已实现的服务与网络配置

菜单“Jev 服务与网络”可编辑服务商、完整接口地址、模型、密钥环境变量名，以及直连/指定 HTTP(S) 代理。OpenRouter 与 TypeSafe 官方提供可编辑预设，其他服务填写兼容 Decisions / System One 的完整地址和自己的模型 ID；不假设任何聊天接口都能作为 Jev 接口使用。

默认网络为直连，没有统一固定端口。直连使用独立连接代理对象，忽略代理环境变量；指定代理使用用户填写的完整地址，不允许 NO_PROXY 环境变量绕过，也不在失败后改走直连。这些设置只影响 Jev，不修改额度等全局连接。当前支持无认证的 HTTP(S) 代理，不支持 SOCKS 或在代理 URL 中保存账号密码；指定代理需要 Node.js 24.5+，现用 Electron 44.3.0 内置 Node 24.20.0 已验证。

连接保存为独立数据文件 jev-settings.json，仅保存地址、模型和环境变量名，不保存实际密钥；发布打包排除此文件。默认 OpenRouter 的环境变量名为 OPENROUTER_API_KEY，TypeSafe 预设为 TYPESAFE_API_KEY，也可以自行填写其他名称。桌宠进程读取环境变量，新增后需要重启。

“测试连接”使用当前未保存的表单，只发送固定测试句；会产生少量模型费用，不读取用户聊天。测试不会自动保存或启用功能。关闭对话框、保存新配置或退出服务时取消相关测试；旧对话框迟到的取消请求不能取消新测试。响应重定向不跟随，服务错误正文不直接显示。

## 以发送事件确定上下文

对成功提交的用户消息使用稳定 messageId、threadId、composerRevision 和本地单调事件序号。它们只在本机用于配对、去重和失效处理，不必上传。点击发送、快捷键发送与提问卡提交最终应归并成同一类成功提交事件；草稿修改、点击后提交失败、工具消息、子代理消息和历史回放都不是用户成功发送。

事件身份优先使用真实提交 ID；缺少稳定身份时不能用每次监听产生的新 UUID 绕过去重。真正从现有数据源获得这些字段，是接入验证项目，不能将模拟字段当成已具备的能力。

### 推荐配对

保存当前聊天、当前输入轮次最近一次实际展示的完整推荐快照，包括 displaySequence 和 texts。同一轮次若有多个推荐，作为一个快照，发送时与其中的候选比较。

1. 只使用 displaySequence 严格早于 submitSequence、且聊天与输入轮次相同的推荐。
2. 草稿变化导致推荐失效、推荐撤回、聊天切换或新轮次开始时，旧快照作废。发送时复制当时快照，之后不再改配对。
3. 用户先发送、推荐后来才出现，只走用户消息分支，不追溯得意。
4. 无法证明推荐已经展示、时序无法确定、文本不完整或来源不匹配时，也走用户消息分支。不能用日志写入先后来冒充界面展示先后。
5. 对比结果代表内容一致或采纳，不代表“点击了按钮”。

发送本身提供来源聊天，不再要求先证明用户一直停在某个前台聊天才允许分析。若返回前已观察到切换聊天、再次发送、隐藏窗口或关闭开关，结果失效。可靠的切换信号尚需接入确认；缺失时不能声称已通过这一展示测试。

### 长度与归一化

初始待测上限：用户消息 300 个 Unicode 码点。先处理 CRLF 为 LF，再去掉首尾空白并做 NFC 归一化；以归一化后的完整消息计数。超过上限、空消息或只有附件时，本地跳过，不调用 Jev，不截断后分析。附件内容不读取。

有推荐时也遵守用户消息上限。推荐候选每条不超过 300 码点、总计不超过 900 码点；超限时整体不提供推荐，转用户消息分支，不挑着截断。

归一化不去掉否定词、标点、代码、数字或内部空白，不做 NFKC 兼容折叠。完全相同在本地标为 exact；其余关系交给 Jev 判断含义。稍改标点不必直接判拒绝；“按 A 做”和“不要按 A 做”也不能用相似度混为一谈。

## 两条判断路径

| 发送时的证据 | 发给 Jev 的内容 | 允许的结果 |
| --- | --- | --- |
| 有有效的先前推荐，用户消息合格 | 当前用户消息、配对推荐、exact/different 的本地比较结果 | 一致或等义采纳且适合回应时得意；强情绪也可庆祝/陪伴；否则安静 |
| 推荐尚未出现、无效或无法配对，用户消息合格 | 仅当前用户消息，加固定的任务说明和台词适用条件 | 仅用户自己的强烈积极/消极情绪才可能触发庆祝/陪伴；不允许得意 |
| 用户消息超长、空、附件，无成功发送事件 | 不请求 | 安静 |

用户消息分支不发送最近助手回复、旧聊天、工具输出或旧推荐。模型固定指令和固定台词不算历史上下文。所有自然语言都作为待分析内容，不能执行用户文本或引语中改变判定规则的指令。

“强烈情绪”针对用户本人当前明确表达的强烈喜悦、挫折或疲惫，不只看感叹号，也不把引用、代码、测试文本或别人说的话当成用户情绪。强烈情绪并不自动要求开口：赶工、拒绝打扰、没有适用台词时仍安静。

同义采纳但带附加修改时，应判断 modified，而非直接得意；明确否定或矛盾时判 rejected。混合情绪或无法确定时保守处理。无需推断用户心理诊断。

## Jev 的问题与决策

使用所选兼容决策服务与配置中的模型，不固定供应商或自动切换供应商。OpenRouter 默认预设为 typesafe/jev-1.13，TypeSafe 默认预设为 jev-latest，用户可编辑。连接测试与自动判定共用网络实现。[OpenRouter 接口参考](https://openrouter.ai/docs/api/api-reference/alphadecisions/submit-a-decisions-request)、[TypeSafe 接口说明](https://docs.typesafe.ai/introduction/quickstart)

一次请求问四个独立问题：

| 字段 | 类型 | 结果 |
| --- | --- | --- |
| relation | choice | adopted、modified、rejected、unavailable |
| emotion | choice | strong_positive、strong_distress、weak_or_none、uncertain |
| hold_back | noul | 用户是否明确要求安静、拒绝额外反馈，或正在紧迫赶工 |
| occasion | choice | 整体收工、跑通且释然、难题解决、写代码休息、修改工作休息、其他休息、证据不足 |

没有 chat 类别，也没有主动找桌宠聊天的特例。内容一致的判断不承诺实际点击来源。几个问题独立计算，必须由本地策略联合使用。

当前策略：hold_back 小于 0.50。庆祝/陪伴要求对应强情绪类别概率至少 0.80，并有概率至少 0.65 的合适台词情境；不能把一小步完成说成收工。得意规则要求有效推荐、relation=adopted、本地 exact 或 adopted 概率至少 0.80，且 weak_or_none 至少 0.80，不让得意覆盖强烈负面情绪。

语气由上述证据与用户明确设定的人设决定，不再对“应该用得意语气吗”增加一层容易重复否决的泛化分数。这个变化修正了此前已识别采纳却不反馈的问题。当前自动来源没有推荐，所以得意规则只在隔离的可信快照测试中使用。

没有阻止理由不代表必须说话，仍须满足采纳或强情绪和语气条件。这里不再沿用旧的宽泛“值不值得开口”分数：新版首轮 16 个样例中，旧 0.80 阈值压掉了全部 4 个预期开口，连 exact 采纳也只得到 0.77。故将判断收窄为明确阻止理由，并另用独立样例验证，不只降低阈值追求原样本全对。

这些阈值通过合成样例验证，未经真实用户长期校准，不是准确率承诺。choice confidence 与类别概率不互相替代；运行时校验枚举、有限概率、分布及字段完整性。

## 台词与轻量呈现

[用户台词目录](intent-dialogue.json) 原文保留。运行时加载 assets/dragon-maiden-reactions.json 中的九句固定台词，chat 三句仅在文档存档。实际来源只走强情绪路径，得意台词等待可信草稿采集接通。自称“本龙”偶尔使用，避免连续重复。

先根据结果和当前短消息中的证据缩小候选：部分工作完成不能说“收工”，没有程序运行证据不能说“跑通”，非代码工作不能说“代码先晾着”，正在赶工不能劝休息。没有符合前提的台词就安静，不额外调用生成模型补一句。

本地轮换合格候选，同一句不连续出现；同类全部候选都因事实前提或防重复而不可用时，不强行说话。单句之间的概率分散不等于语气不确定，不把 tone 阈值硬套到近义台词的排名。

强反馈指一条清楚、贴近本次发送的气泡，配合已有轻量角色反馈，不表示加音效、抢焦点或连续说话。缺少开口依据时保持安静，不先弹一个虚假的得意占位。

### 时机与优先级

- 成功提交后立即构建快照并发起请求，目标发送后 1 秒内可见；这只是待实测目标。
- 从成功提交到首次展示最多 2 秒。总时限涵盖事件发现、网络连接、Jev 和呈现；超过即丢弃。读取日志若已花掉时限，也不补发。
- 一次最多一个反应气泡，展示约 2.5 秒，不排队、不追问；新一次发送使上次候选失效。
- 重要提问/授权优先，主动气泡不能覆盖。额度查看或用户正在操作菜单时不抢占。AI 反应可替换随机台词；占用期间暂停随机台词计时，旧随机文案不补播。
- AI 反应不积压完成统计；与现有完成统计冲突时先保留已有业务展示、丢弃 AI 反应。用户发送后仍展示旧业务气泡的情况列入测试。
- 关闭本功能不等于关闭原有随机文案，两个设置分开标明。关闭时仅清掉本功能自己的气泡，不清掉真实提问。
- 本期不增加交互入口、焦点或新的气泡按钮。现有角色遮挡问题及停留避让暂缓，不能宣称这次已解决。

## 分析次数与打扰控制

允许每条合格短消息各分析一次，不再沿用“5 分钟一次、每小时 3 次”的旧建议。限制服务于去重、及时性和异常控制，而非过度节省 Jev 费用。

初始待测参数：每个消息 ID 最多一次请求；同时只保留最新一个候选；每分钟最多 30 次请求，异常超限直接跳过，不积压。新发送使旧请求等待失效，尽可能取消连接；已抵达服务端的费用不能撤回。

展示单独控制：两次主动气泡至少间隔 10 秒，同一条台词不连续出现。间隔内允许正常分析，但结果不排队、不延期展示。这个数值待实测调整，不作为产品已定死的配置项扩张。

失败不自动重试，不转直连。认证失败停止本次开启周期的后续请求，并在设置中显示错误；代理或临时服务失败进入 30 秒的本地退避，期间不轮询，退避后只由新的合格发送事件触发下一次尝试。错误状态不能被记录为用户意图。

## 关闭、竞态与数据边界

每个候选绑定 enableEpoch、消息身份、推荐快照和截止时间。关闭再开启会改变 enableEpoch，旧请求即使后来成功也无效。新发送、聊天切换、窗口隐藏、重要提醒出现时清理相关候选；窗口恢复不补播。展示前再次检查开关、身份、时限与气泡优先级。

所有 Jev 网络请求遵循用户选择的直连或指定代理方式；选择代理时失败不直连，不自动跟随重定向。密钥取配置指定的环境变量，仅放服务请求的 Authorization 头，不写入日志、文档、renderer 或命令行参数。远程服务要求 HTTPS，本机测试服务可用 HTTP。

本用户设备需要 http://127.0.0.1:7897；这属于本机配置与本次实测约束，不是对其他用户的硬编码默认值。本次真实外网测试均使用该代理。其他端口及直连通过本地假服务验证，没有在本用户设备上对真实 Jev 服务尝试直连。

只在本功能开启时临时持有必要短消息与推荐；发送后不保存长期对话记忆。普通诊断记录长度、分支、决策、耗时和错误类型，不记录消息正文或密钥。模拟验证产物位于忽略目录 qa-output/，真实消息不能默认写入这些文件。

## 已接入的来源及剩余限制

SendingSource 使用 fs.watch 接收会话文件增量，只接受带稳定消息 ID、原始时间和 user.text 元数据的新增主线程纯文本。启动先建立 EOF 基线，之后才进入就绪状态；关闭、重启、历史副本、子代理与注入指令不会作为新用户消息回放。结构化提问卡回复只使旧候选失效，不把其包装文本上传。

已定位本机 Codex 的 requestUserMessagePrediction：预测文字渲染在带 inert 和 aria-hidden 的 span[data-cumberbatch] 中，显示/提交遥测只带身份和统计；正式发送记录没有完整预测文本或展示证明。日志、会话、数据库及辅助功能检查未建立可读取的完整快照来源。RecommendationSnapshots 已验证同一聊天/轮次、先后顺序、失效与 Unicode 边界，但尚无真实采集端驱动它。

因此尚未完成输入框自动草稿配对，也没有可靠的前台聊天 ID 切换事件。新的发送会使旧候选失效；原生隐藏、模式切换和业务提醒会取消候选并清理反应。仅切换 Codex 内部聊天但没有发新消息、没有隐藏窗口的时序仍不能声称已验证。

真实 Codex 提交到会话落盘的延迟不可由日志中的两个时间字段相减推算；本次完整基准从合成消息落盘开始，不能据此承诺真实点击发送到文字出现的总时延。

## 提问误报修复

回放历史异步提问不再重新创建实时等待气泡；保留内存中的请求身份以识别后续真实回答。启动还会清除启动时间之前的异步提醒，覆盖已经不在最近 64 个会话扫描范围内的旧通知，且保留启动后新建的提醒和授权通知。

实时异步问题仍跨正常轮次完成保留，直到回答或明确取消。保守取舍是：重启时即使某条旧异步问题实际上还有效，也不会凭历史记录恢复提醒；这不取消 Codex 中的问题，只改变桌宠的显示。

## 测试与历史证据

详细安排见 [测试计划](INTENT-AWARENESS-TESTS.md)，把隔离策略验证、真实 Jev 合成情境实验和桌面端到端验收分开。

本版隔离输入准备原型通过 25 个检查，验证输出分支、上传字段、300 码点边界、先后顺序、错配和快照独立性。它没有接入真正的 Codex 事件源，也不证明产品已经能够关闭监听或取消网络。

在首次 16 个样例发现旧开口阈值过度保守后，修改问题并重跑这 16 个开发样例，另用 12 个未参与修改的独立样例验证。修改后共 28 个最终动作中 24 个符合预设，零次错误开口，4 次漏报均为预期的得意反应。模型正确识别了采纳关系，但 tone 在 proud 与 silent 间分散，其中独立集的两例直接偏向 silent。这说明“识别采纳”与“按既定人设及时反馈”仍未完全衔接；本轮不继续降低全部阈值来掩盖问题。

独立集已用于评估本版，之后如据此修改策略，应另备验证集。得意分支需要进一步明确固定人设和已开启反馈的意图，并在新样例中确认，不能宣称当前已达到即时强反馈的验收要求。

本次共 44 次模型请求（包含被取代的首轮 16 次），接口返回费用合计 0.002464308 美元，全部经过 7897 代理；输入仅为合成短消息与推荐。记录在 qa-output/intent-awareness/send-reaction-v2/evaluation.json。代理/TLS 与真实桌面事件发现耗时未包含在现有 probe 的 API 计时中，本轮不据此报告发送到气泡的延迟。

此前的 12 个意图场景和 10 个台词场景使用旧策略，原始记录保留于 qa-output/intent-awareness/。它们只证明连接和部分分类能力，不再作为本版“发送前推荐比较、默认关闭、发送后即时反馈”的通过证据。旧聊天开场、必须独立确认采纳、未知输入一律拒绝和低频主动搭话等规则已被本版取代。
